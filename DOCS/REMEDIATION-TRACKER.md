# REMEDIATION-TRACKER · 巩固任务多维表格契约（v8）

> 本文档定义：如何用**一个多维表格**集中维护所有卷子的巩固任务，基于记忆曲线
> （D+1 / D+3 / D+7）自动提醒。目标：不每次生成独立 cron 任务，而是一个表格
> 维护所有待复查知识点，随每次复盘增量写入。

---

## 1. 表格设计

**表格名**：`BeachSOLO 巩固任务`（首次使用时创建，以后永久维护）

**字段设计**：

| 字段名 | 类型 | 说明 |
|---|---|---|
| 知识点 | 单行文本 | 如"政治建设地位""十个明确定位" |
| 关联卷子 | 单行文本 | 如"2025-上海-行测" |
| 错因类型 | 单选 | concept / memory / reasoning / careless |
| 首次复习日期 | 日期 | D+1（复盘次日） |
| 第二次复习日期 | 日期 | D+3 |
| 第三次复习日期 | 日期 | D+7 |
| 掌握状态 | 单选 | 待复习 / 复习中 / 已掌握 / 需加强 |
| 最近作答结果 | 单选 | 正确 / 错误 / 未测 |
| 备注 | 多行文本 | 变式题链接、易错点、口诀 |
| 创建时间 | 创建时间 | 自动 |
| 最后更新 | 最后更新时间 | 自动 |

---

## 2. 记忆曲线规则

| 复习轮次 | 间隔 | 触发条件 | 动作 |
|---|---|---|---|
| 第 1 次 | D+1 | 待复查知识点写入表格时自动设置 | 提醒重做变式题 |
| 第 2 次 | D+3 | 第 1 次答对后设置 | 提醒默写口诀+做 1 道变式 |
| 第 3 次 | D+7 | 第 2 次答对后设置 | 提醒限时模块练习 |
| 掌握 | 三轮全对 | 标记"已掌握" | 不再提醒，归档 |

**任何一轮答错**：回到 D+1 重新开始，备注里记录错误原因。

---

## 3. 工作流

### 3.1 首次使用（创建表格）
```bash
# 用 lark-base 创建多维表格
lark-cli bitable +create --name "BeachSOLO 巩固任务" --format json
```
记下 `app_token` 和 `table_id`，写入 `beachsolo/profile.json` 的 `remediationTracker` 字段，
以后每次复盘直接复用，不重复创建。

### 3.2 每次复盘（增量写入）
步骤 4.1 判定为 pendingPoints 的知识点，逐条写入表格：
```bash
lark-cli bitable +record-create \
  --app-token "<app_token>" --table-id "<table_id>" \
  --fields '{"知识点":"政治建设地位","关联卷子":"2025-上海-行测","错因类型":"concept","首次复习日期":"2026-10-22","掌握状态":"待复习"}'
```
日期用 `calculator` 工具计算（D+1 / D+3 / D+7），禁止凭感觉填。

### 3.3 复习提醒（集中维护，不每次建 cron）
两种实现方式（选一种，在 profile.json 里记录）：

**方式 A：多维表格自动化（推荐）**
- 在表格里设置自动化规则：当"首次复习日期"=今天 且"掌握状态"=待复习 → 发飞书消息提醒
- 优点：不需要 cron，表格自带自动化，集中维护
- 缺点：需要用户在飞书多维表格里手动配置一次自动化规则

**方式 B：每日扫描 cron（兜底）**
- 创建一个每日 cron 任务（`doubao-cron-scheduler`），每天早上扫描表格里
  "复习日期=今天 且 掌握状态≠已掌握"的记录，发提醒
- 优点：全自动，不需要用户配置
- 缺点：需要维护一个长期 cron 任务

**默认用方式 A**，方式 B 作为兜底（用户明确要求时创建）。

### 3.4 复习结果回写
用户完成复习后，在对话里回报"对/错"，agent 更新对应记录：
- 答对 → 掌握状态推进到下一轮，设置下一次复习日期
- 答错 → 回到 D+1，备注记录错误原因
- 三轮全对 → 标记"已掌握"

---

## 4. 硬规则

1. **一个表格维护所有卷子**——禁止每次复盘创建新表格；
2. **首次创建后记录 app_token**——写入 profile.json，以后复用；
3. **日期用工具计算**——D+1/D+3/D+7 用 calculator 算，禁止凭感觉；
4. **已掌握的不删除**——标记状态，保留历史可追溯；
5. **不重复写入**——写入前先查表格，同知识点+同卷子已存在则更新状态，不新建。

---

## 5. 降级链

| 故障 | 降级方案 |
|---|---|
| lark-base 不可用 | 巩固任务写入 `beachsolo/plans/remediation-<date>.md`，用 cron 每日提醒（降级为独立任务） |
| 自动化规则不生效 | 创建每日扫描 cron（方式 B）兜底 |
| 表格权限不足 | 引导用户连接飞书账号后重试，或降级为本地文件 |

任何降级必须在交付说明中明确告知用户。
